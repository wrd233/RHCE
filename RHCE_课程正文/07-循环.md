# 循环

循环不是为了炫技，而是把“同一种任务对很多数据重复执行”压缩成一个 task。第 17 题批量创建用户就是最典型的考试场景。

旧式写法有很多 `with_*`：`with_items` 循环列表，`with_dict` 循环字典。Ansible 2.5 以后更推荐统一使用 `loop`。所以你在备考中要**看得懂 with\_items/with\_dict，但优先练 loop**。

### 列表循环：每一轮的数据都叫 item

```
- name: create files
  file:
    path: "/opt/{{ item }}"
    state: touch
  loop:
    - file1
    - file2
    - file3
```

如果列表放在变量里，`loop: "{{ files }}"`。核心不在语法，而在“task 的模块参数里哪些位置随着 item 变化”。

### 字典循环：先把结构变成可迭代的列表

`with_dict` 每一轮 item 会带 `key` 和 `value`；如果你用 loop，则常见做法是 `dict2items`：

```
vars:
  users:
    alice: 1001
    bob: 1002

tasks:
  - debug:
      msg: "{{ item.key }} -> {{ item.value }}"
    loop: "{{ users | dict2items }}"
```

这正好把下一章 Jinja2 filter 的概念提前串起来：过滤器不是只做“字符串美化”，也可以改变数据结构，让它适合后续操作。

### 考试里更常见的是“列表里放字典”

模拟题的 user\_list.yml 往往不是一个简单字符串列表，而是类似：

```
users:
  - name: user1
    uid: 2001
    job: developer
  - name: user2
    uid: 2002
    job: manager
```

这时直接 `loop: "{{ users }}"`，然后用 `item.name`、`item.uid`、`item.job`。再叠加 `when: item.job == 'developer'`，就完成“循环 + 分类”。

**小优化：**有些模块本身支持一次传列表，例如软件包模块的 `name` 可以是列表。为了可读性和效率，真实项目里不一定每次都 loop；但考试里按题目表达清楚更重要，不必为了“最优雅”增加复杂度。

### 从一个列表逐步走到第 17 题

先看最简单的列表：`loop: [php, mariadb]` 会让 `item` 依次等于两个包名。把它换成字典列表后，`item` 就是一整条用户记录，我们要从中取出 `item.name`、`item.uid`、`item.job`。请先对数据结构做一次 `debug: var=item`，再写用户模块，这比一边猜字段一边调试密码更稳。

```yaml
users:
  - name: alice
    uid: 1101
    job: developer
  - name: bob
    uid: 1102
    job: manager
```

第 17 题的第一段 play 面向 dev/test，只处理 `item.job == 'developer'`，密码来自 `pw_developer`，附加组是 `devops`；第二段面向 prod，只处理 manager，密码来自 `pw_manager`，附加组是 `opsmgr`。两段都从 `user_list.yml` 和加密的 `locker.yml` 读数据。`loop` 负责逐条取人，`when` 负责筛选职位，`hosts` 负责主机范围；三个选择器各管一层。

```yaml
- name: Create developers
  hosts: dev:test
  become: true
  vars_files:
    - user_list.yml
    - locker.yml
  tasks:
    - ansible.builtin.group:
        name: devops
        state: present
    - ansible.builtin.user:
        name: "{{ item.name }}"
        uid: "{{ item.uid }}"
        groups: devops
        append: true
        password: "{{ pw_developer | password_hash('sha512') }}"
      loop: "{{ users }}"
      when: item.job == 'developer'
```

`append: true` 表示保留用户已有的其他附加组；如果题目要求精确限定组成员关系，再按要求决定是否使用。密码哈希还涉及盐值：每次运行生成不同哈希可能使任务反复 changed，应该在实际 Ansible 环境中验证重放结果，并按版本文档选择稳定方案。我们目前展示的是题目结构和数据流，不能凭静态 YAML 声称已在考场环境通过。

### 循环结果为什么有一个 results 列表

如果循环中的 task 使用 `register: package_result`，Ansible 保存的是每轮结果组成的 `package_result.results`，而不是单个 `rc` 或 `changed`。调试时先 `debug: var=package_result.results`，再决定是否要从每轮结果里取出 item、状态或标准输出。这个细节适合在你已掌握普通 loop 后再看；第 17 题主要检查能否按列表和职位正确创建用户，不需要为了显示技巧把循环写复杂。

### 三个小循环，把旧语法也读懂

批量创建 `group1`、`group2`、`group3` 时，老写法 `with_items: [group1, group2, group3]` 与新写法 `loop: [group1, group2, group3]` 都让每轮 `item` 成为一个组名。若字典中有 `alice: {name: Alice, telephone: 123-456-7890}`，老写法 `with_dict: "{{ users }}"` 让每轮有 `item.key` 和 `item.value`；新写法通常把 `users | dict2items` 交给 `loop`。能识别旧语法即可，新练习优先用 `loop`。

另一个例子先在远端执行 `ls /home`，把结果注册为 `home_dirs`，再遍历 `home_dirs.stdout_lines` 为每个目录创建软链接。它提醒我们：循环的数据不一定事先写在变量文件里，也可能来自前一个任务的结果；但用 `ls` 解析文件名不够稳，真实项目更适合找专用模块或结构化返回值。第 17 题用户列表是题面提供的 YAML，所以直接对 `users` 循环即可。

**随堂小测：**为什么第 17 题不能简单写 10 个 user task？

<details markdown="1"><summary>答案</summary>

技术上可以，但题目把用户数据放在外部列表里，就是在考“数据驱动”。正确模型是一份用户数据 + 一个 user task + loop + when，这样用户数量变化时逻辑不用改。
