# 文件内容修改模块

文件管理不只有 copy。lineinfile 和 blockinfile 解决的是“我要在既有配置文件里精确维护一行或一段内容”。

### lineinfile：维护“一整行”的目标状态

我把它说直白一点：它不是对某个关键字做局部字符串替换，而是通过 regexp 找到一行，然后让这一整行达到你指定的 `line`。常用参数包括 `path`、`regexp`、`line`、`insertbefore`、`insertafter`、`backup`、`create`、`validate`、`backrefs`。

```
- name: set SELinux line
  lineinfile:
    path: /etc/selinux/config
    regexp: '^SELINUX='
    line: 'SELINUX=disabled'
    backup: yes
```

它的幂等性来自“匹配 + 目标行”：第二次跑时，如果那一行已经正确，就不会不断追加重复内容。

### insertbefore / insertafter：不是替换，而是确定插入位置

例如我们可以在 `#Port 22` 后插入 `Port 2222`。实际使用时要注意，原配置里可能已经存在其他 Port 行，所以考试之外的生产场景会更重视 regexp 设计，避免重复定义。

### validate：先在临时文件上做配置语法验证

这是非常实用但经常被忽略的参数。模块修改文件前，可以把候选内容交给目标程序自己的校验器，例如 httpd 的 `httpd -t -f %s`。`%s` 会被临时文件路径替换。也就是说 Ansible 不理解 httpd 配置语法，它只是把“提交前验一下”这个动作交给 httpd 自己。

### backrefs：正则替换语义要特别小心

这里要记住：`backrefs: true` 时要求 regexp 真正匹配，没匹配就什么也不做；普通模式下没匹配可能按参数规则插入 line。你在考试里如果只是“确保一整行存在/被替换”，通常不需要复杂 backrefs；知道它是给正则捕获组替换用的即可。

### blockinfile：维护一整段内容

它和 lineinfile 的核心差异是 `block:` 可以放多行，并且默认用 BEGIN/END marker 标出这段内容。下次运行时它通过 marker 找到自己负责的块，实现更新或删除。

```
- name: maintain managed block
  blockinfile:
    path: /opt/abc
    create: yes
    block: |
      abc
      123
      456
```

如果 `state: absent`，它会按 marker 移除这块受管理内容。你可以自定义 marker，但最好保持能唯一识别。

我按“拥有文件的多少内容”选模块：整份文件且内容固定，用 `copy`；整份文件需要变量，用 `template`；只维护一行，用 `lineinfile`；维护一段，用 `blockinfile`；对多处文本做正则替换，才考虑 `replace`。

### 先判定“整份文件”还是“其中一部分”

第 13 题要求把 `/etc/issue` 的**整个内容**替换为一行指定文本。这里 `copy: content:` 更直接，三个组用 `when: "'dev' in group_names"` 等条件分别写 `Development`、`Test`、`Production`。如果用 `lineinfile`，可能留下旧行，验收就不符合“替换整个内容”。注意按题面拼写 `Development`，不要误写成 `Devlopment`。

相反，如果题目说“确保 sshd 配置中的 Port 为 2222，同时保留其余配置”，这才适合 `lineinfile`。`regexp` 要能同时匹配注释掉的旧值和已生效的旧值，让第二次运行仍只留一个目标行。改完先做配置语法验证，再考虑重载服务；远程访问配置尤其不能只看 task 返回 changed 就结束。

```yaml
- name: Keep the SSH port line
  ansible.builtin.lineinfile:
    path: /etc/ssh/sshd_config
    regexp: '^#?Port\\s+'
    line: 'Port 2222'
    validate: 'sshd -t -f %s'
```

需要管理一整块配置时，我会用 `blockinfile` 的 marker 把自己的责任范围标出来。它方便以后更新和删除这块内容，但如果目标是完全由模板控制的文件，用 `template` 会更清楚。**选择模块时先看“我拥有整个文件，还是只拥有其中一行、一块”。**

### 课内几个动作放到同一份文件上看

`lineinfile` 可以用 `regexp` 替换匹配行，用 `insertbefore`/`insertafter` 决定缺失行插入的位置，用 `state: absent` 删除匹配行；`create: true` 则允许目标文件尚不存在时创建。`validate` 会在提交变更前调用程序自己的检查命令。`backrefs: true` 适合需要引用正则捕获组的替换，但未命中时通常不会插入新行。你可以拿一个临时配置文件逐项练，观察每次运行的文件差异，别直接拿 `/etc/ssh/sshd_config` 做第一次实验。

`blockinfile` 管理一段多行文本，默认 marker 明确标出开始和结束。比如要在代理配置里插入一块后端列表，后续再次运行会更新 marker 包围的那块，而不是无限追加。`state: absent` 则移除这个受管理块。模块会修改配置文件，并不自动保证服务能接受配置；校验与服务重载仍要单独设计。

### 用临时文件复现行与块的行为

我们先拿 `/tmp/sshd_config.practice` 练，避免第一次试验就改远程登录配置。假设文件里有 `#Port 22`，`lineinfile` 用 `regexp: '^#?Port '` 和 `line: 'Port 2222'` 把整行规范到目标值；如果要确保一个原来没有的映射行存在，则设置 `line: '192.168.1.99 foo.lab.net foo'`，必要时加 `create: true`。删除匹配行则用 `state: absent` 配合 `regexp`。再跑第二遍，观察它是否会重复插入。

```yaml
- name: Keep one user-specific SSH block in a practice file
  ansible.builtin.blockinfile:
    path: /tmp/sshd_config.practice
    create: true
    marker: '# {mark} ansible-agent settings'
    block: |
      Match User ansible-agent
      PasswordAuthentication no
```

这段块会带有 BEGIN/END marker，下一次运行能找到并更新自己的内容。若将来要把这块删掉，用同样的 marker 与 `state: absent`。碰到 `/etc/sudoers` 之类要求严格语法的文件，我们还可以加 `validate: '/usr/sbin/visudo -cf %s'`，先检查候选文件再保存。第 13 题仍然是整份 `/etc/issue` 的替换，应回到 `copy: content:`，别因为刚学了 `lineinfile` 就什么都用它。

<!-- EXERCISE -->

**随堂判断：**“配置文件 95% 都一样，但不同主机 Listen IP 不同”应该选 lineinfile 还是 template？

<details markdown="1"><summary>答案</summary>

更适合 template。lineinfile 适合在既有文件中维护少量行；如果整份配置是一个受控模板、只是若干值随主机变化，template 更清晰。

</details>
