# 从 13 章走到 19 道模拟题

学完章节后，我会把复习顺序倒过来：不再按模块重读，而是按题目要求完整交付文件、运行、验证。题目答案只是一种实现参考，真正的交付条件是受管节点复位以后，控制节点保存的项目还能把它们配置到目标状态。这一点既写在模拟题说明里，也符合红帽当前对实践考试的公开描述。

| 题号 | 题目要求 | 先抓住的判断 | 最后怎么验证 |
|---|---|---|---|
| 1 | 配置 Ansible、静态清单、角色与集合路径 | dev/test/prod/balancers 的成员，以及 prod 是 webservers 的子组 | `ansible --version`、`ansible-inventory --graph`、`ansible all -m ping` |
| 2 | 所有节点配置 BaseOS 和 AppStream 仓库 | `yum_repository` 的两个仓库段及 GPG 选项 | 查看 `.repo` 文件并运行 `dnf repolist` |
| 3 | 按组安装包、包组并更新软件 | 三种目标范围应分别表达 | `rpm -q`、`dnf group list --installed` 和运行结果 |
| 4 | 使用 Timesync 系统角色 | 读角色 README，找到 NTP 服务器变量 | `chronyc sources` |
| 5 | 使用 SELinux 系统角色 | `targeted` 与 `enforcing` 是目标状态 | `getenforce` 和配置持久性 |
| 6 | 从要求文件安装两个角色 | 名称 `balancer`、`phpinfo` 与 `roles_path` | `ansible-galaxy role list -p roles/` |
| 7 | 安装两个 Collection | 安装路径与执行器搜索路径一致 | `ansible-galaxy collection list -p mycollections/` |
| 8 | 创建 apache 角色并部署首页 | 模块、模板、服务、防火墙组合；只在 webservers 运行 | 分别 `curl serverc` 和 `curl serverd` |
| 9 | 调用 balancer 与 phpinfo 角色 | 两个目标组对应两个 play | 访问负载均衡入口和 `/hello.php` |
| 10 | 创建 LVM，容量不足时回退 | 先判断卷组是否存在，再在 600/400 MiB 间回退 | `lvs`、`blkid`；题目明确不挂载 |
| 11 | 选择磁盘、分区、格式化并挂载 | 优先 vdd，否则 vdb；容量失败再回退 | `lsblk -f`、`findmnt /mnt/fs01` |
| 12 | 为 dev 组生成主机文件 | `groups` 列举主机，`hostvars` 取各主机 Facts | 对照 `/etc/myhosts` 与真实 IP/FQDN |
| 13 | 按组替换 `/etc/issue` 内容 | 目标是整份文件，按组决定唯一一行 | `cat /etc/issue`，特别检查 `Development` 拼写 |
| 14 | 创建 Web 内容目录 | 目录 2775/SGID、软链、SELinux、HTTP 是一条链 | `curl .../webdev/`、`ls -ldZ` |
| 15 | 生成硬件报告 | 下载模板、用 Facts 填值，缺失设备写 `NONE` | 逐台检查 `/root/hwreport.txt` |
| 16 | 创建并加密密码变量文件 | Vault 文件、密码文件与两项变量要分清 | `ansible-vault view` 与文件加密状态 |
| 17 | 从用户列表批量创建用户 | hosts、loop、when、Vault、哈希各管一层 | `id`、`getent shadow` 与重新运行 |
| 18 | 更新现有 Vault 的密钥 | 使用 rekey，保持文件加密 | 新口令可解、旧口令不可解 |
| 19 | 给 natasha 创建计划任务 | 在 dev 组，每两分钟运行 `echo hello` | `crontab -u natasha -l` |

## 哪些内容要学深，哪些先学到“会判断”

清单、配置、Playbook 结构、常用模块、变量与 Facts、条件、循环、角色、模板、Vault 和运行验证，是这套题的骨架，应该练到能从空目录重建。`lineinfile` 的高级正则、Jinja 的大量过滤器、复杂 Execution Environment 定制，则先理解适用场景，碰到具体要求再查文档；不要让扩展知识打断主线。对第 10、11 题这样的存储题，心智模型比记住某份 YAML 更重要：**先确认对象存在，再尝试目标大小，失败时按题面回退，最后验证最终设备状态。**

## 模拟题和当前官方目标的边界

这套模拟题有明确的练习主机、路径和 19 个任务，但它不是正式考试题目清单。红帽当前公开的 [EX294 考试目标](https://www.redhat.com/en/services/training/ex294-red-hat-certified-engineer-rhce-exam-red-hat-enterprise-linux) 列出 Ansible 基础组件、清单与配置、Playbook、角色和集合、Vault，以及自动化软件仓库、服务、存储、文件、计划任务等；还列出使用 `ansible-navigator`/`ansible-playbook`、管理节点连接与提权、Git 基础操作和在 VS Code 中创建及运行 Playbook。后面这两项没有在本套 19 题中形成单独题目，复习时应另做一次短练习：克隆练习仓库、添加和提交文件；在可用的 VS Code/开发容器环境里打开项目并运行一次 Playbook。是否需要推送以及具体界面步骤，以你参加的考试版本和现场条件为准。

红帽也说明考试会在新装系统上应用考生编写的 Playbook 并检查目标状态。因此我们每完成一题都要问：**如果节点回到初始状态，只保留控制端项目，我还能复现吗？** 这比“当前机器看起来已经配置好”更接近真正的验收方式。
