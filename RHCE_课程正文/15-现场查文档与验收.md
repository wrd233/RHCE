# 现场查文档与验收

一道题读完，只要我们能回答“目标主机是谁、系统对象是什么、最终状态是什么、有没有循环或条件、最后如何验证”，就可以开始查本机文档，不需要先在脑子里拼出完整 YAML。现场是否提供哪种资料，要以考试当时的规则和环境为准；红帽公开说明多数考试会提供随产品安装的文档，但不提供互联网访问。

| 已经知道什么 | 可以查哪里 | 希望查到什么 |
|---|---|---|
| 知道模块名 | `ansible-doc -s MODULE` 或 `ansible-doc FQCN` | 参数骨架、返回值和例子 |
| 只知道功能 | `ansible-doc -l` 后按关键词筛选 | 候选模块及其集合 |
| 需要主机硬件/系统信息 | `ansible HOST -m setup` | 实际 Facts 名称与数据结构 |
| 需要 System Role | 本地角色 `README.md` | 角色名、变量名、最小示例 |
| 需要 Vault、Galaxy、Navigator 命令 | 各命令的 `--help` | 参数、路径与调用方式 |
| 配置项忘了 | `ansible-config list`、`ansible-config dump --only-changed` | 当前版本接受的键和实际生效值 |

写好以后按四层检查：先做语法检查；再看目标主机集合；然后真正运行；最后到受管节点检查包、服务、文件、端口、账户或挂载状态。`changed=0` 不是失败，也不是成功的充分证明；它只表示模块认为当前状态不需要更改。真正能说明完成的是题面要求的结果在目标节点上可见，并且重新运行仍能保持这一结果。

涉及密码、存储或远程连接时，尤其要保留“问题发生在哪一层”的判断：Vault 解不开先看密码文件和路径；模块找不到先看 Collection 与执行环境；受管节点 unreachable 先看清单与 SSH；LVM 或分区失败先看设备和容量。这样排错才不会回到盲改 YAML。
