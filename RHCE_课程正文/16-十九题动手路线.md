# 19 道题的动手路线

我现在把章节知识再合成一套完整练习。下面的主机名、路径、URL 和文件名都取自当前这套模拟题；它们是练习条件，不代表正式考试会给出同样的数值。每道题都按“交付文件 → 关键判断 → 目标状态”来读，做完再回到上一节的验收表逐项检查。

## 第一段：把项目搭起来（1—3）

**1．安装和配置 Ansible。** 在控制节点按题面确认 `ansible-core`、`ansible-navigator`，以 devops 身份建立 `/home/devops/ansible`，在 `inventory` 中放入 dev/servera、test/serverb、prod/serverc+serverd、balancers/bastion，并让 webservers 包含 prod。`ansible.cfg` 指向这份清单、`roles` 与 `mycollections`；完成后先看 `ansible-inventory --graph`，再做 `ansible all -m ping`。模拟题准备说明里的 SSH 密钥、容器仓库和清理旧仓库操作是练习环境准备，题面已有条件时先验证，无须照抄。

**2．创建受管节点仓库。** `yum_repo.yml` 面向 all，用两个 `ansible.builtin.yum_repository` 任务分别写 `rh294_BASE` 和 `rh294_STREAM`。前者指向 `http://content.example.com/rhel9.0/x86_64/dvd/BaseOS`，后者指向同根目录的 `AppStream`；描述分别是 `rh294 base software`、`rh294 stream software`，两者都启用 GPG 检查和仓库，密钥地址为该 DVD 目录下的 `RPM-GPG-KEY-redhat-release`。让 `file: rhel_dvd` 把它们放入同一 `.repo` 文件，再核对文件和仓库可用性。

**3．安装软件包。** `packages.yml` 用三个 play 表达三个目标集合：dev/test/prod 安装 php、mariadb；dev 安装 `@Development Tools`；dev 把已装包更新到 latest。这里主要练“hosts 决定在哪做、模块决定做什么”，不用把三种目标范围硬塞进一个任务。更新所有包可能产生较大变化，练习时按题面执行，别把这段无条件搬到其他机器。

## 第二段：复用角色与集合（4—9）

**4．配置时间同步。** `timesync.yml` 面向 all，调用当前环境可用的 Timesync RHEL System Role，使用角色 README 中的变量结构把 NTP 服务器设为 `classroom.example.com`，并按题意启用当前可用的时间同步配置。运行后到节点看 `chronyc sources`；只看角色返回 ok，不能证明真的使用了目标时间源。

**5．配置 SELinux。** `selinux.yml` 面向 all，调用 SELinux RHEL System Role，目标是 `selinux_policy: targeted` 和 `selinux_state: enforcing`。按角色说明设置提权，运行后检查 `getenforce` 以及重启后配置。调试时可以在临时练习节点观察状态变化，但不要把人为切成 Permissive 当成正式交付步骤。

**6．安装 Galaxy 角色。** 在 `roles/requirements.yml` 为 `http://classroom.example.com/content/haproxy.tar.gz` 指定名称 `balancer`，为同目录的 `phpinfo.tar.gz` 指定名称 `phpinfo`；再安装到项目 `roles/`。`requirements.yml` 是交付文件的一部分，只有“当前机器上恰好装好了”而没有可重建的要求文件，练习就不完整。

**7．安装 Collection。** 将 `http://content.example.com/ansible-posix-1.5.1.tar.gz` 和 `community-general-6.3.0.tar.gz` 安装到 `mycollections/`，确认目录下能看到对应命名空间，并且当前 Ansible/Navigator 能按配置路径加载。这里的名字和版本是这套题指定的内容，不应自动替换成网络上最新版本。

**8．创建 apache 角色。** 在 `roles/apache` 中完成 `tasks/main.yml`、`templates/index.html.j2`。角色要安装并启用 httpd，启用 firewalld 并放行 HTTP，模板输出 `Welcome to HOSTNAME on IPADDRESS`，其中两个占位值分别来自目标主机的 FQDN 与 IP Fact；`newrole.yml` 只对 webservers 调用该角色。运行后分别访问 serverc 和 serverd，检查输出中的主机名与地址确实属于当前节点。

**9．组合已有角色。** `roles.yml` 的一个 play 面向 balancers 调用 `balancer`，另一个面向 webservers 调用 `phpinfo`。前者把 Web 请求分发到后端，后者让 `/hello.php` 显示对应主机的 FQDN 和 PHP 信息。用多次 `curl` 检查入口与两个后端；负载均衡的访问结果可能因策略和请求状态而变化，核心是两个后端都能被服务。

## 第三段：让条件、模板和文件完成系统状态（10—15）

**10．创建逻辑卷。** `lv.yml` 面向 all：若 `research` 卷组存在，先创建 600 MiB 的 `data`，容量不够时输出 `Could not create logical volume of that size` 并改为 400 MiB；若卷组不存在，输出 `Volume group does not exist`。成功创建后格式化为 ext4，题目明确要求不挂载。先用 Facts 判断 VG，失败分支再用 `block/rescue`，最终设备是否存在要独立确认；不要让 `always` 无条件对不存在的逻辑卷操作。

**11．创建分区。** `parted.yml` 面向 dev：有 `/dev/vdd` 优先用它；如果它不存在，先输出题面要求的 `disk /dev/vdd does not exist`，再尝试 `/dev/vdb`。所选磁盘先尝试 1500 MiB，失败时输出 `Could not create partition of that size` 并改为 800 MiB，随后做 ext4 并挂载 `/mnt/fs01`。两个候选设备都不存在时还要说明 vdb 缺失。前提是目标磁盘确实可用于本题，不能把模拟题中为腾出磁盘而写的 `dd`、删除 PV/VG/LV 等重置命令放进交付 Playbook。

**12．生成主机文件。** `hosts.j2` 先写两行 localhost，再遍历 `groups['all']`，从 `hostvars[host]` 取得每台机器的 IP、FQDN 和短名；`hosts.yml` 只在 dev 组把模板写到 `/etc/myhosts`。要让模板可取到每台主机的 Facts，先对相关节点收集 Facts。题目允许主机行顺序不同；比较时看信息是否完整、地址是否来自真实环境。

**13．按组修改 issue。** `issue.yml` 面向所有清单主机，但 dev/test/prod 分别把 `/etc/issue` 的完整内容设成 `Development`、`Test`、`Production` 加换行。三个 `copy: content:` 任务各挂一个组条件就足够；如果同一台机器同时属于多个目标组，要先根据题面决定最终应由哪一组控制，不能让后一个任务随意覆盖前一个。拼写必须以题面为准。

**14．创建 Web 内容目录。** `webcontent.yml` 面向 dev，建立组为 devops、模式为 `2775` 的 `/webdev`，在其中写一行 `Development` 到 `index.html`，再建立 `/var/www/html/webdev` 指向该目录的软链接。httpd 要运行，HTTP 访问要能通过防火墙和 SELinux。用 `ls -ldZ /webdev` 看目录权限与上下文，再用 `curl http://servera.lab.example.com/webdev/` 看最终页面。

**15．生成硬件报告。** `hwreport.yml` 面向 all，先把 `http://172.25.254.254/content/hwreport.empty` 下载到 `/root/hwreport.txt`，再按空模板中的键替换为清单主机名、内存 MB、BIOS 版本、vda/vdb 容量；不存在的设备填 `NONE`。`get_url` 后接多个 `replace` 是这套答案展示的方法，整份文件也可以在明确允许的情况下用模板生成；无论采用哪种方式，都要保留题面要求的键名和 `key=value` 格式。

## 第四段：保护数据并把用户、计划任务落到系统里（16—19）

**16．创建 Vault。** 在项目里创建含 `pw_developer: Imadev` 与 `pw_manager: Imamgr` 的 `locker.yml`，用题目给定口令 `fgydsxsxsbxs` 加密，口令文件是 `secret.txt`。之后用 `ansible-vault view --vault-password-file secret.txt locker.yml` 验证可解，同时确认文件内容仍是密文。练习口令只属于这份模拟材料，不应用于真实账户。

**17．批量创建用户。** 下载 `user_list.yml` 后先看 `users` 的真实数据结构。`users.yml` 在 dev/test 节点仅创建 `job: developer` 的用户，加入 devops 附加组，密码来自 `pw_developer`；在 prod 节点仅创建 manager，加入 opsmgr，密码来自 `pw_manager`。两段都引入用户列表和 Vault 文件，用户名/UID 从每个 item 取，密码转成 SHA512 哈希。运行时提供 `--vault-password-file secret.txt`，再用 `id` 与账户数据库验证，最后重复运行检查稳定性。

**18．更新 Vault 口令。** 下载已有的 `salaries.yml`，用 `ansible-vault rekey` 把题面给出的旧口令 `insecure4sure` 换成新口令 `bbe2de98389b`，文件必须保持加密。此题只针对 salaries 文件；别改第 16 题 `locker.yml` 的口令文件。核对时用新旧口令分别尝试 view。

**19．创建计划任务。** `cron.yml` 面向 dev，确保 natasha 用户存在，随后用 `ansible.builtin.cron` 创建每两分钟执行一次 `echo hello` 的任务：`minute: '*/2'`、`job: echo hello`、`user: natasha`。完成后到 dev 节点执行 `crontab -u natasha -l`，核对调度表达式、命令和用户身份。

做到这里，我们再从空白控制端项目复盘一次：是否有题目要求的每个文件、每个路径、每个用户权限？能否只凭保存的项目内容重新配置初始节点？如果答案是肯定的，再去检查界面上是否显示了想要的 `ok/changed`，学习顺序就不会被表面输出带偏。
