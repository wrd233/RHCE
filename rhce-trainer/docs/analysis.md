## 安全边界

仅通过官方 rht-vmctl 管理 workstation/servera/serverb/serverc/serverd/bastion；utility/classroom 为共享基础设施，不重置。每个虚拟机名称与 UUID 绑定。拒绝 all/everything、任意命令、未知 VM。f0 只读检查及官方 save/restore/reset；不安装软件、不修改其网络/SSH/服务。官方 fullreset 内部会删 VM 保存点并更新 known_hosts，因此默认不使用；完全恢复练习节点采用明确 baseline restore。

首次已核实各磁盘无保存点，官方 reset 返回原始镜像，随后准备考试公共前提并创建命名基线。后续只能显式恢复该命名基线，不能用会挑选最新 save 的裸 reset。评分结束在 finally 恢复评分前 VM；中断留下本地 journal，可运行 recover。备份含答案或密码文件的可能性，保存在用户目录外置私有状态区，权限 700/600，不入仓库。

## 依赖与隔离

依赖图以 questions.json 为准。基础 inventory/config 不从学生旧答案猜测；reset 发现需替换时先备份。不为目标题写答案。第 9 题提供 6/7/8 前置，第 17 题提供 16 前置；10/11 总是从已验证空数据盘基线准备。每个 reset 恢复题目涉及的完整 VM，**这些 VM 上其他手工状态会回到基线**，此前现场保留为恢复点；不涉及的 VM 不变。控制节点仅移走题目指定产物，已有其他答案保留。评分恢复所有被重建的 VM，并保留学生文件。

## 验收原则

checkpoint = id / description / weight / check / status / evidence。总分 100。源码约束用 Ansible 自身解析与执行事件，不与标准 YAML 文本比较。有效主机清单必须不包含外部机器；运行时限制到授权节点。无法完成基线恢复、依赖准备、采集或回滚是基础设施 ERROR，不能伪装成学生 0 分或通过。评分依赖学生运行成功，失败后可报告独立结果，但不得拿基线既有状态充当已完成证据。

实测 fresh 原始镜像：a–d 均有空白 1 GiB vdb，bastion 无 vdb，httpd/php/mariadb 未安装；firewalld **运行中**，与 PDF 概述“不启用”不同。基线保留真实镜像的服务起点，不把参考说明假装成现场事实。首启网络初始化约 2 分钟，SSH 可达不代表启动即刻稳定。
